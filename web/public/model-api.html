Start with credit, not a subscription

  1. Sign in with a passkey and open Model API in your account.
  2. Add US$20, US$50 or US$100 when top-ups are open.
  3. Create a key with a lifetime spending limit and an expiry. Copy it once.
  4. Set your tool’s base URL to https://bountyoperator.com/v1 and use the model ID shown above.

API credit and the Operator review subscription are separate purchases. No API subscription or automatic top-up is required.

Python quickstart

Use the OpenAI Python client. Keep your key in an environment variable, outside source control.

Clients must support the Chat Completions API. Anthropic’s Messages API, OpenAI Responses, images, audio and embeddings are not supported by this endpoint.

Endpoints and parameters

MethodPathReturns
GET/v1/modelsAvailable models, limits and rates
POST/v1/chat/completionsA response or an SSE stream; supports function tools
GET/v1/usageYour available wallet and this key’s spending limit

Authenticate with Authorization: Bearer YOUR_KEY. Chat requests accept text messages, tools, tool_choice, parallel_tool_calls, response_format, temperature, top_p, top_k, penalties, seed and stop. Set either max_tokens or max_completion_tokens. Only one completion per request is supported.

For this Qwen model, extra_body={"chat_template_kwargs": {"enable_thinking": False}} disables thinking in the Python client. Reasoning tokens count as output tokens.

Requests are limited to 256 messages, 32 tools and 256 KiB of JSON. Each account can run two requests at once. The pilot serves four requests at once across accounts. When capacity is full, a 429 response includes a retry delay.

Set stream_options.include_usage to receive token counts at the end of a stream. An interrupted stream may end with a coded error. Use the request ID to find its charge in your account.

An optional Idempotency-Key prevents the same key from starting twice for 30 days. A repeat returns 409; responses are not stored for replay. Use a new value only when you intend to start a new generation.

How requests are charged

The live catalog above and /v1/models show the current input rate, output rate and minimum request charge. The charge is the greater of the token cost or that minimum whenever usage has been confirmed, including an interrupted request. A request with no confirmed usage is not charged.

Before generation, enough credit is reserved for the model’s full input context and your requested output limit. The final charge uses the model’s token counters. The unused reservation is released when the request ends. Keep enough available credit for the reservation as well as the expected charge.

Keys stop spending at their lifetime limit. A refund or chargeback removes the corresponding credit and may suspend further requests until the balance is settled. Unused credit does not expire; see the API credit terms for refunds.

The first request after idle can take longer while the worker starts. A timeout is not a completed answer. The gateway allows up to three minutes for startup and five minutes for generation. Set a ten-minute client timeout and respect retry headers.

Your content passes through

Requests pass through Cloudflare to our vLLM deployment on Runpod. Prompt and response logging is disabled. We do not save prompts or responses in our application database. Cross-request prefix caching is disabled.

We retain API key hashes, limits, token counts and billing records. Recent request metadata is deleted after 30 days. Infrastructure providers process traffic under their own policies. Read the full data handling details.

For authorized security work

The available model is a community fine-tune; its source, exact revision, quantization and license are shown in the catalog. Passing our compatibility checks is not a security benchmark or a promise that its findings are correct. Check scope, evidence and conclusions yourself.

Use the service only on code, data and systems you are authorized to assess. The API generates text and tool calls; your client controls whether a tool executes.
